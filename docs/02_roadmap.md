# 02_roadmap.md

## Назначение документа
Документ описывает пошаговый путь создания MVP проекта
«Цифровой двойник инвестиционных проектов Гатчины»
от пустой папки до завершённого локального веб-сервиса.

Роудмап ориентирован на **соло-разработку** с неполной занятостью.
Каждый этап фиксирует **проверяемое состояние системы**, а не просто список задач.

---

## Общая оценка сроков
- **Календарно:** ~3–4 месяца
- **Чистое время:** ~120–180 часов
- **Режим:** 1–3 часа в день, не каждый день

---

## Этап 0. Подготовка и фиксация основы  
**Срок:** ~1 неделя (5–8 часов)

### Задачи:
- Подготовить `00_concept.md`, `01_architecture.md`, `02_roadmap.md`. [готово]
- Создать структуру репозитория (frontend / backend / data / docs).   [готово]
- Инициализировать Git-репозиторий (не забыть gitignore).             [готово]

### Результат этапа:
- Есть репозиторий с документацией.
- Архитектура и план не вызывают сомнений.
- Можно начинать разработку без хаоса.

---

## Этап 1. Базовый каркас проекта  
**Срок:** ~1 неделя (8–12 часов)

### Задачи:
- Создать пустой frontend-проект (Vue + Vite).                        [готово]
- Создать минимальный backend (Flask, health-check).                  [готово]
- Настроить локальный запуск frontend и backend.                      [готово]
- Проверить, что сервисы стартуют без ошибок.                         [готово]

### Результат этапа:
- Frontend открывается в браузере.
- Backend отвечает на тестовый запрос.
- Нет бизнес-логики, но есть рабочая связка.

---

## Этап 2. Слой данных проектов (моки)  
**Срок:** ~1 неделя (8–12 часов)

### Задачи:
- Создать папку `data/projects/`.                                     [готово]
- Подготовить ~10 мок-проектов (минимальный набор данных).            [готово]
- Реализовать на backend:                                             [готово]
  - чтение проектов из файловой структуры;                            [готово]
  - эндпоинт получения списка проектов;                               [готово]
  - эндпоинт получения одного проекта.                                [готово]
- Подключить frontend к API.

### Результат этапа:
- Frontend получает список проектов с backend.
- Проекты отображаются в простом виде (без карты).
- Система работает с файловыми данными.

---

## Этап 3. Интерактивная карта  
**Срок:** ~1–1.5 недели (10–15 часов)

### Задачи:
- Подключить Yandex.Maps JS API v3.
- Отобразить карту города.
- Разместить маркеры проектов по координатам.
- Обработать клик по маркеру.

### Результат этапа:
- Карта — основной экран.
- Все проекты отображаются на карте.
- Пользователь может выбрать проект через карту.

---

## Этап 4. Карточка проекта  
**Срок:** ~1 неделя (8–12 часов)

### Задачи:
- Реализовать UI карточки проекта.
- Отобразить основные данные проекта.
- Обработать отсутствие части данных (гибкость).
- Связать карточку с выбором маркера.

### Результат этапа:
- По клику на маркер открывается карточка.
- Пользователь видит информацию о проекте.
- UI устойчив к изменению структуры данных.

---

## Этап 5. Серверный расчёт (минимальный)  
**Срок:** ~1–1.5 недели (12–18 часов)

### Задачи:
- Реализовать `POST /calculate`.
- Подготовить минимальный Calc Engine:
  - приём параметров;
  - расчёт заглушек (NPV / IRR / Payback).
- Вернуть результат в фиксированном JSON-формате.
- Добавить версию расчётов (`calc_version`).

### Результат этапа:
- Сервер выполняет расчёты.
- Формулы не находятся на фронте.
- API возвращает воспроизводимый результат.

---

## Этап 6. Финансовый виджет  
**Срок:** ~1–1.5 недели (12–18 часов)

### Задачи:
- Реализовать форму ввода параметров.
- Отправлять параметры на backend.
- Отображать KPI.
- Построить графики денежных потоков (Chart.js).

### Результат этапа:
- Пользователь может менять параметры.
- Видит пересчёт KPI и графиков.
- Виджет работает стабильно.

---

## Этап 7. Сравнение проектов  
**Срок:** ~1 неделя (8–12 часов)

### Задачи:
- Реализовать выбор нескольких проектов.
- Запуск расчётов для каждого проекта.
- Отобразить сравнительную таблицу KPI.
- Обработать UX (удаление, пересчёт).

### Результат этапа:
- Можно сравнить 2–3 проекта.
- Таблица и данные обновляются корректно.
- Функция реально полезна инвестору.

---

## Этап 8. Фильтрация и навигация  
**Срок:** ~1 неделя (6–10 часов)

### Задачи:
- Добавить базовые фильтры проектов.
- Синхронизировать фильтры с картой.
- Улучшить навигацию и UX.

### Результат этапа:
- Проекты легко отбирать.
- Карта и интерфейс работают согласованно.
- Пользователь быстрее принимает решения.

---

## Этап 9. Импорт / экспорт данных  
**Срок:** ~0.5–1 неделя (6–8 часов)

### Задачи:
- Реализовать экспорт snapshot данных.
- Реализовать импорт snapshot.
- Добавить базовую валидацию данных.

### Результат этапа:
- Данные можно сохранить и восстановить.
- Упрощено тестирование и резервное копирование.

---

## Этап 10. Стабилизация и полировка  
**Срок:** ~1 неделя (8–12 часов)

### Задачи:
- Устранить критические баги.
- Проверить сценарий «запуск с нуля».
- Упростить код и убрать технический мусор.
- Проверить соответствие архитектуре.

### Результат этапа:
- MVP работает стабильно.
- Нет блокирующих ошибок.
- Проект готов к демонстрации.

---

## Этап 11. Финальная фиксация MVP  
**Срок:** ~0.5 недели (4–6 часов)

### Задачи:
- Написать README с инструкцией запуска.
- Зафиксировать версию MVP (git tag).
- Подготовить проект к показу заказчикам/преподавателям.

### Результат этапа:
- MVP завершён.
- Проект можно передать или демонстрировать.
- Есть чёткая точка «готово».

---

## Что не входит в роудмап
- Продакшен-развёртывание.
- Авторизация и роли.
- Интеграции с внешними системами.
- Масштабирование и оптимизация.

---

## Правила работы с роудмапом
- Этап закрывается только при достижении результата.
- Возврат к этапу допускается, но фиксируется.
- Если с этапом проблемы то допускается дробление, но не усложнение всего плана.
